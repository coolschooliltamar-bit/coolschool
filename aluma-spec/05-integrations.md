# 05 – חיבור לפלטפורמות חיצוניות

> **הסיכון הגדול ביותר בפרויקט.** אלומה שווה רק כמו המידע שהיא יכולה לקרוא. לפני כל השקעה בפיתוח מחבר – לברר מה מותר ומה אפשרי באופן רשמי.

## עקרונות

1. **רק דרכים רשמיות.** API רשמי, OAuth, או הסכם עם מפעיל המערכת. **לא** גרידת אתרים (scraping) ולא שימוש בסיסמת המשתמש במערכת אחרת – זה מסוכן, עלול להפר תנאי שימוש, ושובר בכל שינוי עיצוב.
2. **קריאה בלבד**, מלבד שליחת הודעות מאושרות.
3. **Scopes מינימליים** – מבקשים רק את ההרשאות שצריך.
4. **כל מחבר מבודד** ומממש ממשק אחיד.

## ממשק מחבר אחיד

```ts
interface ConnectorAdapter {
  provider: Provider;                       // 'demo' | 'google_classroom' | 'mashov' | ...
  capabilities: Capability[];               // ['grades','assignments','schedule','messages:read','messages:send']
  connectUser?(userId: string): Promise<AuthUrl>;          // OAuth
  sync(scope: SyncScope): Promise<SyncResult>;             // מושך ומנרמל לטבלאות records_*
  fetchFresh?(query: FreshQuery): Promise<NormalizedRecord[]>; // שליפה מיידית כשהמטמון ישן
  sendMessage?(msg: ApprovedMessage): Promise<SendResult>; // רק עבור pending_action מאושר
  revoke(userId: string): Promise<void>;
}
```

## מצב המערכות (נכון לכתיבה – חלק נדרש אימות)

| מערכת | מה יש בה | דרך חיבור | סטטוס |
|-------|-----------|-----------|--------|
| **מחבר דמה** | נתוני דמה מלאים | פנימי | ✅ ל-MVP ולהדגמות |
| **Google Classroom** | קורסים, מטלות, הגשות, ציוני מטלות, הודעות כיתה | **Classroom API רשמי** עם OAuth 2.0 של Google. בבתי ספר עם Google Workspace for Education ייתכן שנדרש אישור מנהל הדומיין לאפליקציה | ✅ אפשרי – יעד ראשון למחבר אמיתי |
| **משוב** | ציונים, נוכחות, מערכת שעות, הודעות | **לא ידוע לנו על API ציבורי רשמי.** קיימים כלים לא רשמיים – **לא להשתמש בהם**. נדרשת פנייה לחברה המפעילה | ❓ נדרש אימות – `Q-01` |
| **מערכות משרד החינוך** (הזדהות, פורטלים) | זהות, נתוני תלמידים | ככל הידוע לנו אין API פתוח לגורמים חיצוניים. נדרש שיתוף פעולה רשמי | ❓ נדרש אימות – `Q-01` |
| **Webtop / מערכות בית ספריות אחרות** | משתנה | לבדוק מול כל מפעיל | ❓ |
| **Zoom** | קישורי שיעור | Zoom API קיים, אבל בדרך כלל הקישור מגיע דרך Classroom/משוב | ⏸ לא ב-MVP |
| **וואטסאפ** | הודעות בקבוצות כיתה | אין דרך רשמית לקרוא קבוצות. WhatsApp Business API מיועד לשליחה מעסקים | ❌ לא קוראים קבוצות. ערוץ שיחה עם אלומה – `Q-04` |

## Google Classroom – פירוט (מחבר אמיתי ראשון)

- **OAuth scopes (הצעה, לאמת מול התיעוד של Google):** קריאת קורסים, קריאת מטלות וההגשות של המשתמש עצמו, קריאת הודעות הכיתה. **לא** לבקש הרשאות כתיבה ב-MVP.
- **מה נקרא:** קורסים → `classes`; מטלות + סטטוס הגשה + ציון → `records_assignments` / `records_grades`.
- **סנכרון:** בהתחברות; אחר כך כל 30 דקות בשעות 07:00–22:00; ושליפה מיידית כשמשתמש שואל והמטמון בן יותר מ-15 דקות.
- **אישור אפליקציה:** אפליקציות OAuth שניגשות להרשאות רגישות עשויות לדרוש אימות של Google לפני שימוש רחב. לבדוק את הדרישות מוקדם (`Q-02`).
- **שליחת הודעות:** Classroom לא מיועד להודעות פרטיות כלליות. ערוץ השליחה למורה – `Q-10`.

## שליחת הודעות למורה – אפשרויות

| אפשרות | יתרון | חיסרון |
|--------|-------|--------|
| דרך מערכת ההודעות של בית הספר (משוב) | המורה רגיל לקבל שם | תלוי ב-API שאולי לא קיים |
| דוא"ל מחשבון בית הספר של התלמיד (Gmail API) | API רשמי | דורש הרשאת שליחה רגישה |
| תיבת הודעות בתוך אלומה (המורה רואה באפליקציה/מקבל התראה) | שליטה מלאה, אין תלות | המורה צריך להשתמש באלומה |

המלצה ל-MVP: **תיבת הודעות בתוך אלומה** + התראה בדוא"ל למורה ("יש לך הודעה חדשה מתלמיד"), עם תוכן ההודעה רק בתוך אלומה.

## נרמול נתונים

כל מחבר ממפה לפורמט אחיד (ראו טבלאות `records_*` ב-03):
- מקצועות: מיפוי שמות ("היסט׳", "History") לשם קנוני. טבלת מיפוי לכל בית ספר.
- ציונים: `score` + `max_score` (לא מניחים 100).
- תאריכים: שעון ישראל לתצוגה, UTC לאחסון.
- זהויות: התאמה בין משתמש אלומה למשתמש במערכת המקור דרך `external_ids`, לא לפי שם.

## טיפול בכשלים

| כשל | תגובה |
|-----|--------|
| טוקן פג / בוטל | סימון `connector_accounts.status = 'reauth_required'`, הודעה למשתמש "צריך להתחבר מחדש ל-Classroom" |
| מגבלת קצב של ה-API החיצוני | Backoff אקספוננציאלי, דחיית סנכרון |
| שינוי בפורמט | הבדיקות החוזיות (14) נכשלות → התראה לצוות; המחבר מושבת עד תיקון |
| מערכת לא זמינה | מענה מהמטמון עם "נכון ל-..." |

## צעדים מיידיים

1. לבנות את מחבר הדמה עם נתונים מלאים (הבסיס לכל הפיתוח וההדגמות).
2. לפתוח פרויקט Google Cloud, להגדיר OAuth ולבדוק את Classroom API עם חשבון בדיקה.
3. לנסח פנייה רשמית למפעילי משוב ולמשרד החינוך: מי אנחנו, מה רוצים לקרוא, איך שומרים על פרטיות (`Q-01`).
