## רכיבים

| רכיב | אחריות | טכנולוגיה מוצעת |
|------|--------|------------------|
| Web App | ממשק שיחה, כרטיסי נתונים, אישור פעולות | React + TypeScript, PWA, RTL |
| API Gateway | TLS, אימות טוקן, הגבלת קצב, לוגים | Fastify (או Reverse proxy מנוהל) |
| Auth & Permissions | התחברות, סשנים, תפקידים, בדיקת הרשאה לכל גישה | OIDC (Google / SSO בית ספרי) + מודול הרשאות פנימי |
| Conversation Service | שמירת שיחות והודעות, סטרימינג לתשובות | Node.js, SSE |
| AI Orchestrator | בניית ההקשר, ניהול לולאת כלים מול Claude, טיפול בסירוב/שגיאות | Anthropic TypeScript SDK |
| Tool Executor | מריץ כלים שה-AI ביקש – **תמיד** עם זהות המשתמש מהסשן, לא מה-AI | קוד TypeScript |
| Pending Actions | שמירת טיוטות, הצגה לאישור, שליחה רק אחרי אישור | טבלה + תור |
| Connector Workers | סנכרון תקופתי ומיידי ממערכות חיצוניות, נרמול לפורמט אחיד | Workers על תור (BullMQ/Redis) |

| Secrets / KMS | הצפנת טוקנים של מערכות חיצוניות | שירות KMS של ספק הענן |

## זרימה: שאלה פשוטה

1. התלמיד שולח "כמה קיבלתי בהיסטוריה?" → Gateway מאמת את הסשן.
2. Conversation Service שומר את ההודעה ופותח זרם תשובה (SSE).
3. AI Orchestrator בונה בקשה ל-Claude: הנחיות מערכת קבועות (נשמרות במטמון), הקשר משתמש מינימלי (תפקיד, כיתה, תאריך), היסטוריית שיחה קצרה, והגדרות כלים.
4. Claude מבקש את הכלי `get_grades({subject: "היסטוריה", limit: 1})`.
5. Tool Executor מריץ את הכלי **עם `user_id` מהסשן** – ה-AI לא יכול לבחור משתמש אחר. נבדקת הרשאה, נשלפים נתונים מהמטמון (או סנכרון מיידי אם ישנים).
6. התוצאה חוזרת ל-Claude, שמנסח תשובה קצרה עם מקור וזמן עדכון.
7. התשובה מוזרמת למשתמש; נרשם אירוע ב-Audit Log.

## זרימה: שליחת הודעה למורה

1. "תנסחי למורה שאני חולה" → Claude קורא ל-`draft_message_to_teacher(...)`.
2. הכלי **לא שולח**. הוא יוצר `pending_action` עם הטיוטה ומחזיר מזהה.
3. הממשק מציג כרטיס אישור: נמען, נושא, גוף ההודעה, כפתורי "עריכה" / "אישור ושליחה".
4. רק לחיצה של המשתמש (קריאת API נפרדת `POST /actions/{id}/confirm` עם אסימון חד־פעמי) שולחת את ההודעה דרך המחבר המתאים.
5. ה-AI לעולם לא יכול לאשר פעולה בעצמו – אין לו כלי כזה.

## עקרונות ארכיטקטוניים

- **ההרשאות בשרת, לא במודל.** כל כלי מקבל את זהות המשתמש מהסשן. גם אם ה-AI "ישתכנע" לבקש מידע של מישהו אחר – הכלי יחזיר שגיאה.
- **מקור אמת אחד לכל נתון.** המטמון שלנו הוא העתק; מערכת המקור קובעת. כל נתון נושא `source` ו-`fetched_at`.
- **מחברים מבודדים.** כל מחבר הוא מודול נפרד עם ממשק אחיד (`ConnectorAdapter`) – קל להוסיף מערכת או לנתק אחת.
- **כשל רך.** אם מערכת חיצונית לא זמינה – עונים מהמטמון עם אזהרה ("נכון לשעה 08:10"), לא מנחשים.
- **Multi-tenant מההתחלה.** כל שורה ב-DB שייכת לבית ספר (`tenant_id`), ו-RLS ב-Postgres מונע דליפה בין בתי ספר.

## מגבלות ידועות

- תלות בזמינות ובמדיניות של מערכות חיצוניות.
- זמן תגובה: שאלה עם כלי אחד צפויה לקחת מספר שניות – לכן סטרימינג ואינדיקציה "מחפשת במשוב...".
- ה-MVP הראשון יעבוד עם **מחבר דמה** בלבד, עד שתהיה גישה רשמית למערכות אמיתיות.
