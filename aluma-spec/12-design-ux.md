# 12 – עיצוב וחוויית משתמש

## עקרונות

1. **שיחה במרכז.** המסך הראשי הוא צ'אט. כל השאר – כרטיסים בתוך השיחה.
2. **נתונים ככרטיסים, לא כטקסט.** ציון, מטלה או שיעור מוצגים בכרטיס מובנה שנבנה מהנתונים עצמם – לא מטקסט של AI.
3. **שקיפות מקור.** בכל כרטיס: מאיזו מערכת ומתי עודכן.
4. **פעולה = אישור.** כל פעולה כלפי חוץ מוצגת ככרטיס אישור ברור.
5. **עברית ו-RTL מלאים**, כולל מספרים ותאריכים נכונים בתוך טקסט עברי.
6. **מהיר בטלפון.** רוב השימוש ממובייל.

## רכיבים

| רכיב | תיאור |
|------|-------|
| בועת משתמש | כחולה, טקסט לבן, בצד שמאל (RTL – ההודעות של המשתמש בצד הנגדי לאלומה) |
| בועת אלומה | לבנה/זכוכית, בצד ימין |
| כרטיס ציון | מקצוע · סוג · **ציון גדול** · תאריך · "מתוך משוב · עודכן 08:10" |
| כרטיס מטלה | כותרת · מקצוע · מועד הגשה (אדום אם פחות מ-24 שעות) · סטטוס · "פתח במערכת" |
| כרטיס מערכת שעות | שעה · מקצוע · מורה · חדר / קישור; שינוי מסומן בתגית כתומה |
| כרטיס אישור הודעה | "אל: ..." · נושא · גוף · כפתורים: "עריכה" (משני), "אישור ושליחה" (ראשי), "ביטול" (קישור) |
| צ'יפים להצעות | "מה יש לי מחר?", "ציונים אחרונים", "כתוב למורה" |
| מחוון עבודה | "מחפשת במשוב..." / "מנסחת..." – לא ספינר כללי |
| באנר נתונים ישנים | "המידע נכון ל-08:10 – משוב לא זמין כרגע" |

## זרימות מרכזיות

### התחברות ראשונה (תלמיד)
1. מסך פתיחה: "אלומה · פשוט שואלים" + "התחבר עם Google".
2. הסבר קצר (3 מסכים, ניתן לדלג): מה אלומה עושה, מה היא לא עושה, פרטיות.
3. חיבור מערכות (אם בית הספר לא חיבר ברמת הדומיין).
4. צ'אט עם הודעת פתיחה והצעות.

### שליחת הודעה
```
בקשה → "מנסחת..." → כרטיס אישור → [עריכה בתוך הכרטיס] → אישור ושליחה
     → "נשלח ✓ · המורה תקבל ב-07:30 (שעות שקט)" → אפשרות "בטל" ל-10 שניות
```

## נגישות

- יעד: עמידה בתקן הישראלי ת"י 5568 (המבוסס על WCAG) ברמה AA – לאמת את הדרישה המדויקת מול יועץ נגישות (`Q-14`).
- ניגודיות מינימלית 4.5:1 לטקסט.
- תמיכה בקורא מסך: כרטיסים עם תוויות, הודעות חדשות מוכרזות (`aria-live="polite"`).
- גודל טקסט מתכוונן; פריסה לא נשברת ב-200%.
- כל פעולה זמינה מהמקלדת.
- אפשרות לקלט קולי (Web Speech, אם הדפדפן תומך) – שלב 2.
