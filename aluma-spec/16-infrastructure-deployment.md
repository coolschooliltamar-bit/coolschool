# 16 – תשתיות ופריסה

## סביבות

| סביבה | מטרה | נתונים | גישה |
|--------|-------|--------|------|
| `local` | פיתוח | נתוני דמה בלבד | כל הצוות |
| `staging` | בדיקות לפני שחרור | נתוני דמה בלבד | צוות + מנטור |
| `production` | פיילוט ובתי ספר | נתונים אמיתיים | פריסה דרך CI בלבד; גישה ידנית רק "break glass" |

**אסור** להעתיק נתונים אמיתיים לסביבות אחרות.

## פריסה בענן (הצעה)

| רכיב | שירות (דוגמה ב-AWS `il-central-1`) | חלופה ב-Google Cloud (`me-west1`) |
|------|--------------------------------------|-------------------------------------|
| שרת API ו-Workers | ECS Fargate (קונטיינרים) | Cloud Run |
| מסד נתונים | RDS for PostgreSQL, Multi-AZ, מוצפן | Cloud SQL for PostgreSQL |
| מטמון ותורים | ElastiCache (Redis) | Memorystore |
| קבצים סטטיים (Web App) | S3 + CloudFront | Cloud Storage + CDN |
| סודות | Secrets Manager | Secret Manager |
| מפתחות הצפנה | KMS | Cloud KMS |
| לוגים וניטור | CloudWatch | Cloud Logging / Monitoring |

> בחירת הספק והאזור – `Q-05`. השיקול המרכזי: שמירת המידע בישראל, עלות, ותוכניות הטבה לסטודנטים/סטארטאפים.

## קונטיינרים

- `Dockerfile` רב-שלבי, תמונת בסיס מינימלית (`node:22-slim` או distroless), משתמש לא-root.
- שני תהליכים מאותה תמונה: `api` ו-`worker`.
- בדיקת בריאות: `GET /healthz` (חי), `GET /readyz` (DB + Redis זמינים).

## CI/CD (GitHub Actions)

```
PR:      lint → typecheck → unit → permission tests → integration → build → AI evals (חלקי) → security scans
main:    כל הנ"ל → build image → deploy staging → e2e → [אישור ידני] → deploy production
```

- פריסה ל-production: אישור ידני של שני חברי צוות.
- מיגרציות DB רצות כצעד נפרד לפני עדכון הקוד; מיגרציה הרסנית דורשת אישור מיוחד.
- Rollback: חזרה לתמונה הקודמת בלחיצה; מיגרציות נכתבות תואמות לאחור לגרסה אחת.

## סודות

- מפתח Anthropic API, סודות OAuth, מפתח חתימת סשנים – **רק** ב-Secrets Manager.
- אף סוד לא בקוד, ב-`.env` במאגר או בלוגים. סריקת gitleaks ב-CI.
- מפתח API נפרד לכל סביבה, עם תקרת הוצאה בחשבון Anthropic.
- סבב החלפת סודות: כל 90 יום, ומיד אחרי עזיבת חבר צוות.

## רשת

- DB ו-Redis ברשת פרטית בלבד, ללא כתובת ציבורית.
- תעבורה יוצאת מהשרת: רק לדומיינים מוגדרים (Anthropic API, Google APIs, ספקי SMS/דוא"ל).
- WAF בסיסי לפני ה-API (הגנה מהתקפות נפוצות והגבלת קצב לפי IP).

## ניטור והתראות

| מדד | סף התראה |
|------|-----------|
| שיעור שגיאות 5xx | > 2% במשך 5 דקות |
| זמן תגובה ראשון (TTFB) לשאלה | p95 > 6 שניות |
| שגיאות הרשאה (403) למשתמש | > 20 בשעה – חשד לניסיון גישה |
| עלות AI יומית לבית ספר | > 80% מהתקרה |
| כשל סנכרון מחבר | 3 כשלים רצופים |
| זמינות | < 99.5% בחודש |

התראות לערוץ צוות + דוא"ל לאחראי התורן.

## גיבוי ושחזור

- גיבוי אוטומטי יומי + Point-in-time recovery של 7 ימים.
- גיבויים מוצפנים, באותו אזור.
- תרגול שחזור פעם ברבעון; יעד: RPO 24 שעות, RTO 4 שעות.
