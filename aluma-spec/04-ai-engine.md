# 04 – מנוע ה-AI המרכזי

## תפקיד

ה-AI Orchestrator מקבל הודעת משתמש, מחליט (דרך Claude) אילו כלים להפעיל, מריץ אותם בבטחה, ומחזיר תשובה מבוססת־נתונים. **המודל מחליט מה לשאול; השרת מחליט מה מותר.**

## מודל ותצורה

| פרמטר | ערך | הערה |
|--------|-----|-------|
| מודל | `claude-opus-5-5` | דרך Anthropic TypeScript SDK (`@anthropic-ai/sdk`) |
| Thinking | `{type: "adaptive"}` | לא ניתן לכבות ב-Opus 5.5 |
| Effort | `low` לשאלות שליפה פשוטות, `medium` לסיכומים וניסוח | ב-Opus 5.5 ברירת המחדל היא `medium` – לקבוע במפורש |
| Streaming | כן | תשובות מוזרמות לממשק |
| `max_tokens` | 4,096 לתשובת צ'אט | תשובות קצרות במכוון |
| Fallback בסירוב | `betas: ["server-side-fallback-2026-07-01"]` + `fallbacks: "default"` | חובה לבדוק `stop_reason === "refusal"` |
| Prompt caching | על הנחיות המערכת והגדרות הכלים | ראו "עלויות" |

> מודל זול יותר לניתוב שאלות פשוטות (למשל Claude Haiku 5.5) – החלטה פתוחה `Q-03`. לא משנים מודל בלי מדידה על סט הבדיקות (14).

## מבנה הבקשה ל-Claude

```
tools:    [הגדרות כלים – קבועות, ממוינות]              ← נשמר במטמון
system:   [הנחיות קבועות: זהות, כללים, סגנון – ראו 18]  ← נשמר במטמון
messages:
  - הודעת system בתוך השיחה (משתנה): תפקיד, כיתה, תאריך ושעה, שמות ילדים (להורה)
  - היסטוריה: עד 10 הודעות אחרונות + סיכום שיחה ישנה
  - הודעת המשתמש החדשה
```

**חשוב לקאש:** תאריך, שם המשתמש וכל מידע משתנה **לא** נכנסים להנחיות הקבועות – אחרת המטמון נשבר בכל בקשה.

## כלים (Tools)

כל הכלים מוגדרים עם `strict: true` ו-`additionalProperties: false`. **אף כלי לא מקבל מזהה משתמש** – הזהות מגיעה מהסשן.

| כלי | תיאור | פרמטרים עיקריים | זמין ל |
|-----|-------|------------------|--------|
| `get_grades` | ציונים של התלמיד/הילד | `student_ref?` (להורה: "הילד הנבחר" או שם מתוך רשימה סגורה), `subject?`, `from?`, `to?`, `limit?` | תלמיד, הורה |
| `get_assignments` | מטלות לפי סטטוס ותאריך | `status?`, `due_before?`, `subject?` | תלמיד, הורה |
| `get_schedule` | מערכת שעות ושינויים | `date?` / `range?` | תלמיד, הורה, מורה |
| `get_attendance` | נוכחות | `from?`, `to?` | תלמיד, הורה |
| `get_messages` | הודעות שהתקבלו | `unread_only?`, `from_teacher?` | כולם |
| `list_my_teachers` | רשימת נמענים מותרים | – | תלמיד, הורה |
| `draft_message_to_teacher` | יוצר **טיוטה** (לא שולח) | `teacher_ref` (מתוך הרשימה), `subject`, `body` | תלמיד, הורה |
| `get_class_summary` | סיכום כיתה למורה (מי לא הגיש, ממוצע) | `class_ref`, `assignment_ref?` | מורה |
| `remember_preference` | שמירת העדפה (ראו 11) | `text` | כולם |

`student_ref` להורה הוא **enum** שנבנה בכל בקשה מהילדים המקושרים – המודל לא יכול להמציא ילד אחר.

### פורמט תוצאת כלי

```json
{
  "data": [{ "subject": "היסטוריה", "title": "מבחן – המהפכה הצרפתית",
             "score": 88, "max_score": 100, "date": "2026-11-10" }],
  "source": "mashov",
  "fetched_at": "2026-11-16T08:10:00+02:00",
  "is_stale": false,
  "external_content": false
}
```

אם יש טקסט חופשי ממערכת חיצונית (תיאור מטלה, גוף הודעה) – הוא עטוף כ-`<external_content>` ו-`external_content: true` (הגנה מהזרקה, ראו 02).

## לולאת הסוכן

```
1. בניית בקשה → Claude (stream)
2. אם stop_reason == "refusal" → הודעה מנומסת + לוג (ה-fallback בצד השרת כבר ניסה מודל אחר)
3. אם stop_reason == "tool_use":
     a. ולידציה של הפרמטרים מול הסכמה
     b. בדיקת הרשאה: הכלי זמין לתפקיד? הפרמטרים בתוך התחום?
     c. הרצה (במקביל, אם יש כמה) עם timeout של 8 שניות לכלי
     d. החזרת כל התוצאות בהודעה אחת; שגיאה → tool_result עם is_error: true
     e. חזרה ל-1 (מקסימום 5 סבבים)
4. end_turn → בדיקת עיגון (סעיף הבא) → שמירה והזרמה
```

הגבלה: מקסימום 5 סבבי כלים לשאלה; חריגה ← "לא הצלחתי למצוא, אפשר לנסח אחרת?".

## עיגון ודיוק (נגד "המצאות")

1. **הנחיה:** כל מספר, תאריך או שם בתשובה חייב להגיע מתוצאת כלי בשיחה הנוכחית.
2. **בדיקה אוטומטית אחרי התשובה:** כל מספר שמופיע בתשובה נבדק מול תוצאות הכלים. מספר שלא נמצא ← התשובה נחסמת ומוחלפת בכרטיס הנתונים הגולמי + הודעה "הנה הנתונים כפי שהם במערכת".
3. **כרטיסי נתונים:** ציונים ומטלות מוצגים גם ככרטיס מובנה שנבנה מהנתונים עצמם (לא מטקסט ה-AI), עם מקור וזמן.
4. **נתונים ישנים:** אם `is_stale` – התשובה חייבת לכלול "נכון ל-...".
